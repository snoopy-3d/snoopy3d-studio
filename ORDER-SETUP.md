# Заказы SNOOPY3D

Сейчас включён вариант без сервера: клиент создаёт модель, нажимает «Заказать печать», заполняет форму, скачивает ZIP и вручную прикрепляет его в чат https://t.me/snoopy_3D. ZIP содержит сам STL, order.txt и order.json с параметрами. Открытие Telegram не прикрепляет и не отправляет файл. Регистрация и оплата на сайте не требуются. Цвет STL не сохраняет: цвет указан в заявке.

## Автоматическая доставка: подготовлено, но ещё не подключено

Обработчик `server.mjs` работает на Node.js 22+ без установки библиотек. Его нужно разместить на отдельном сервере с HTTPS и постоянным приватным диском. GitHub Pages для него не подходит. Можно использовать существующий VPS или контейнерный хостинг с постоянным томом. Новые платные ресурсы в ходе этой работы не создавались.

1. Создать бота через официальный @BotFather. Владелец должен открыть своего бота и нажать Start. Имя @snoopy_3D — контакт для ручного потока; оно не заменяет числовой chat_id владельца в Bot API.
2. В секретах серверного хостинга задать TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_ID. Токен нельзя добавлять в файлы, публичный репозиторий, клиентский JS или переписку с заказчиком. Узнать свой chat_id можно по getUpdates своего бота на доверенном сервере; не передавайте токен сторонним ботам для определения ID.
3. Задать ALLOWED_ORIGIN=https://snoopy-3d.github.io, DATA_DIR — путь постоянного приватного тома вне папки статического сайта, PORT — порт хостинга. Запуск из корня проекта: `node server.mjs`. Для контейнера: `docker build -f Dockerfile.orders -t snoopy-orders .` и подключить защищённый постоянный том в /data/orders (UID 1000).
4. Направить HTTPS-прокси на порт обработчика. Ограничить тело запроса 12 МБ и время 70 секунд; доступ к DATA_DIR из интернета запрещён. Запускать ровно один процесс/реплику: блокировки находятся в памяти. Не включать автоматическое масштабирование без общей БД/очереди и распределённой блокировки.
5. В `order-config.js` указать полный HTTPS URL `/orders` в endpoint. Это публичный адрес, не секрет. Не включать endpoint до тестового получения ZIP в собственном Telegram.
6. Пройти реальный заказ с сайта: проверить получение ZIP, открыть STL в Bambu Studio в мм, проверить имя, количество, цвет, контакты, город и параметры в order.json. После этого можно объявить автоматическую отправку включённой.

После включения клиент отправляет STL по HTTPS. Сервер проверяет размер до 8 МБ, структуру бинарного STL, конечные координаты, SHA-256 и поля заявки; сохраняет STL и параметры приватно, затем одним сообщением отправляет ZIP владельцу через Telegram sendDocument. Только ответ Telegram с file_id считается доставкой. Доставка сообщения не означает согласование цены или физическую печать.

Повтор с тем же номером и теми же данными после подтверждённой доставки возвращает прежний успех без нового сообщения. Если Telegram ответил ошибкой или связь оборвалась, сервер сохраняет статус unconfirmed и не пересылает заказ автоматически: сначала владелец проверяет Telegram по номеру заявки. Это предотвращает слепые повторы при неоднозначной доставке. ZIP для ручной отправки остаётся доступен клиенту.

## Эксплуатационные ограничения

Встроено ограничение 5 запросов за 10 минут с адреса соединения, до 100 заявок на диске. После заполнения требуется разбор/архивация владельцем. За обратным прокси адрес может быть общим: заголовок X-Forwarded-For намеренно не считается доверенным. Для широкой рекламы настройте ограничение частоты и защиту от ботов на доверенном HTTPS-прокси. CORS не является защитой от прямых запросов сторонних программ. Лимиты процесса сбрасываются после перезапуска.

В DATA_DIR находятся персональные данные. Ограничьте доступ владельцем, настройте резервное копирование, квоту диска и срок хранения (например, удаление завершённых заявок через 30 дней). Это организационные настройки хостинга; автоматическое удаление в данной версии не включено. Telegram хранит собственную копию сообщения. Удаление файлов на сервере не удаляет её. Отдельный адрес доставки запрашивается владельцем после согласования; сайт собирает только город.

Проверка STL на сервере структурная; пригодность модели к печати, ориентацию, габариты отдельных частей и прочность владелец проверяет в Bambu Studio под P1S. Общие размеры нескольких разложенных деталей могут превышать стол принтера: детали нужно расположить/разделить в слайсере. Физическая печать в этой работе не проводилась.

Проверки обработчика: `node --test server.test.mjs`. Автоматические тесты используют имитацию Telegram; они не доказывают получение в реальном аккаунте.

Документация Bot API: https://core.telegram.org/bots/api#senddocument
